# Agent deployment and hosting for the EU pilot

Research note, gathered 2026-11-03 from vendor docs, pricing pages, DPAs and trust centers. Each claim links the page it came from. "Page date" is the vendor's own last-updated stamp where one is shown. Prices are list prices at the time of reading. Where a page showed only US rates, that is noted; EU rates are usually a little higher.

Workloads in scope: (a) Next.js web app, (b) Prime (Python LangGraph + Claude chat, Teams/Slack bots), (c) background Agent runs after the nightly sync, (d) connector syncs with Playwright + Chromium, sometimes headed for human MFA, (e) Postgres, (f) email. Email (f) was not part of the six questions and is not covered here.

## 5. Anthropic API: residency, retention, and cloud alternatives

- **First-party API, no EU option.** `inference_geo` accepts only `"global"` (default) or `"us"`. Workspace geo (storage and endpoint processing) is "us" only. US-only inference costs 1.1× ([Data residency](https://platform.claude.com/docs/en/manage-claude/data-residency)). The same applies to Claude Platform on AWS and Claude Models on Google Cloud (Anthropic-managed).
- **ZDR.** Requested through sales and enabled per organization. Covers the Messages and Token Counting APIs for eligible features. Excluded: stateful features such as code execution/programmatic tool calling (30-day retention), Managed Agents (nothing eligible), and the "Covered Models" (Fable 5/5.1, Mythos 5/5.1), which need 30-day retention ([API and data retention](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention)).
- **HIPAA readiness.** BAA self-serve from the Console. Permanent once enabled. Blocks ineligible features with a 400 error. Do not put PHI in JSON schemas (same page).
- **Amazon Bedrock (EU).** Claude Sonnet 5.5 has an EU geo profile `eu.anthropic.claude-sonnet-5-5`. From EU source regions it routes only among Frankfurt, Stockholm, Milan, Spain, Ireland and Paris (London as a source adds London). In-region-only processing is **not** offered for 5.5 in EU regions on `bedrock-runtime` ([Sonnet 5.5 model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-sonnet-5-5.html), launched 2026-09-28). AWS says not to trust the prefix alone and to verify destinations with `GetInferenceProfile` ([inference profiles](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-support.html)). On Bedrock, AWS is the processor ([retention doc](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention)).
- **Google Vertex AI (EU).** EU multi-region endpoint `aiplatform.eu.rep.googleapis.com` for all Claude models ≥ 4.7. Endpoint type affects price; the size of the difference is not stated ([partner models](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/partner-models/use-partner-models)). The `eu` multi-region "strictly covers data residency within EU member states" and excludes the UK and Switzerland ([Vertex data residency](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/learn/data-residency)).
- Anthropic's [regional compliance](https://claude.com/regional-compliance) page lists Europe via Bedrock and Vertex, with Microsoft Foundry "coming soon".

## Implications for our choice

1. **The model is the residency bottleneck.** The first-party Claude API offers only `global` or `us`. For EU-only processing of pseudonymized health data, Prime and Agent runs must call Claude through **Bedrock's `eu.` geo profile** or **Vertex's `eu` multi-region**, and the cloud provider becomes the sub-processor. That choice also favours the matching cloud for compute.
2. **Move Vercel to `fra1` and keep the web app and Prime there.** Vercel's DPA still allows US processing, and its static IPs cost $100/mo per project. Fine for the UI. Not where connector egress should come from.
3. **Connectors (d) need a real container host.** Headed Chromium, file exports and Sponsor IP allowlists rule out Vercel Functions and Supabase Edge Functions. Fly.io (`fra`/`ams`, $3.60/mo static egress, scale-to-zero) is the cheapest fit. Cloud Run jobs or Fargate win if we pick Vertex or Bedrock in item 1, at the cost of NAT setup.
4. **Do MFA in-house.** Running our own noVNC or CDP screencast inside the connector container keeps credentials, pages and egress IP in one EU box. Browserbase `eu-central-1` is the managed fallback, but its storage location and BAA need a Scale contract.
5. **Agent runs (c) are short.** Tens to hundreds of few-minute loops fit Vercel Workflows in `fra1`, or a pgmq/pg-boss queue drained by workers on the connector host. Inngest and Trigger.dev store payloads in the US, which is a problem for special-category data. Temporal Cloud EU with payload encryption, or self-hosted Hatchet, are the durable options that keep plaintext ours.
6. **Supabase needs a new project in an EU region (e.g. `eu-central-1`).** The current project is in us-east-1; this note did not check whether a project's region can be changed. Budget for **Team ($599/mo)** if Sponsors ask for SOC 2/ISO reports or HIPAA-style controls. Supabase has no static egress, so any outbound call to a Sponsor must leave from our container host.
